# design-brief

**AIに「かっこいいサイトを作って」と言うのをやめて、作る前に決めることを先に決めるための Claude Code スキル。**

企画書または題材を渡すと、§1〜§9のデザインブリーフが出ます。
`plan → critique → build → critique` の4段構成で、**実装に入る前に筋の悪い案を殺します。**

コードを書けない広告屋が、AIと架空ブランドのサイトを3本作って、**実際に効いた判断だけ**を型にしたものです。デザイン論は入っていません。3本のあいだに実際に踏んだ失敗しか書いていません。

---

## なぜ作ったか

AIにサイトを作らせると、指示が曖昧なぶんだけ**既定値**が出てきます。温かいクリーム地にセリフ体の見出し、あるいはほぼ黒にアシッドグリーン。何度やっても同じ顔になる。

原因は生成の性能ではなく、**渡す前に決めていないこと**でした。

3作作って分かったのは、決めるべきことは毎回同じ9項目だということ。そして**自分で決めないと、AIが勝手に決める**ということです。この型は、その9項目を「答え」ではなく**「問い」**として並べたものです。

## 入れかた

Claude Code のスキルディレクトリに置くだけです。

```bash
git clone https://github.com/UU2134/design-brief.git
cp -r design-brief/skills/design-brief ~/.claude/skills/
```

プロジェクト単位で使うなら `~/.claude/skills/` の代わりに、そのプロジェクトの `.claude/skills/` に置いてください。

## 使いかた

```
/design-brief 架空のコーヒー焙煎所のサイト。豆は1種類だけ。通販はしない。
```

企画書がある場合は、そのまま渡してください。

**使う前に1箇所だけ書き換えてください。** SKILL.md の「過去作の解法一覧」の表は広告屋の3作の実物です。**そのままだと、他人の癖を避けることになります。** 自分の過去作で置き換えてください。1作目でまだ無いなら、**自分がよく参考にするサイト3つ**で埋めてください——避けるべき既定値は、過去作が無くても必ず持っています。

## 中身

### 4段の工程

| 段 | やること |
|---|---|
| **0. 過去作を読む** | 自分の解法一覧を読み、**今回どこを違う解き方にするか宣言する** |
| **0.5. 企画の有無を確かめる** | 誰が何をしに来て／何を持って帰って／このサイトが引き受ける仕事は何か。**答えられなければブリーフを書き始めない** |
| **1. plan** | §1〜§9に仮の答えを出す |
| **2. critique** | 凡庸さ／自己模倣／空洞／勝ち筋の4観点で自分の案を叩く |
| **3. build** | ブリーフを確定して書き出す |
| **4. critique** | 書いたブリーフをもう一度叩く |

### §1〜§9

一言でいうと／色／タイポグラフィ／ワードマーク／ビジュアルの本体／モーションの実装翻訳／一作一ギミック／線引き（やらないこと）／本人レビューで決めたいこと。

**全部、答えではなく問いの形で書いてあります。** 答えを書くと、同じ構成のものが量産されるからです。

### 繰り返していいもの／いけないもの

このスキルの芯はここです。

- **繰り返していい（価値観）** — 大小のコントラストを最大にする／叫ぶのは一語／一作一ギミック／やらないことを先に決める
- **繰り返してはいけない（解法）** — 黒背景／粒／水／スクロール連動の一発ギミック／静けさ

だから§8の禁止リストは4層あります。**①AIの既定値 ②ジャンルの既定値 ③自分の既定値 ④素材。** ①だけ避けても、②と③には落ちます。

## 動かした記録

書いて終わりにせず、実際に1本流しています。**わざと3作の真逆（明るい・うるさい・屋外）の題材**を入れて、型が「暗くて静かなサイトの作り方」に堕ちていないかを試した記録です。

→ [examples/stress-test.md](examples/stress-test.md)

critiqueが3案を殺し、**そのうち1つは過去作で半日磨いてから捨てた案と同じ形**でした。着手前に落ちたので、このスキルを作った目的はそこで達成されています。
